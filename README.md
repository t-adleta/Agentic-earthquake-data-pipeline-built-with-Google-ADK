# Agentic Earthquake Data Pipeline (Google ADK)

An end-to-end data engineering pipeline driven by AI agents built with Google's
[Agent Development Kit](https://adk.dev/). It pulls recent earthquakes from the public
USGS API, cleans and aggregates them, saves raw and processed data to cloud object
storage (Google Cloud Storage or AWS S3), and produces an HTML report with charts.

## How it works

`root_agent` is an ADK `SequentialAgent` that runs four specialist `LlmAgent`s in order.
Each agent owns one stage, decides how to call its tool based on your request, checks the
result and reports it.

| # | Agent | Tool it calls | What happens |
|---|-------|---------------|--------------|
| 1 | `ingestion_agent` | `fetch_earthquakes(period)` | Downloads the USGS GeoJSON feed (past day, week or month) and saves the raw file |
| 2 | `transform_agent` | `transform_earthquakes(min_magnitude)` | De-duplicates, removes non-earthquakes and incomplete rows, filters by magnitude, derives region / magnitude class / depth class, then aggregates by day, class and region |
| 3 | `storage_agent` | `upload_data_to_cloud()` | Uploads the raw file, the clean event table (CSV) and the summary (JSON) to the bucket |
| 4 | `report_agent` | `build_report(insights)` | Reads the summary, writes a short findings paragraph, builds `output/report.html` and uploads it |

Design notes:

- **Data does not pass through the LLM.** Tools write files and pass file *paths* to the
  next stage through ADK session state. The model only sees small summaries, which keeps
  runs cheap and avoids the model altering data.
- **The agents make real decisions.** The request is natural language ("past month,
  magnitude 4.5 and up"); the agents turn it into tool parameters, and the report agent
  interprets the results in writing.
- **Processing logic is plain Python** (`quake_pipeline/processing.py`) with unit tests.

```
quake_pipeline/
  agent.py        agent definitions (root_agent)
  tools.py        the four tools the agents call
  processing.py   cleaning and aggregation (pandas)
  storage.py      GCS / S3 upload
  report.py       HTML report builder
  config.py       settings from environment variables
run_pipeline.py   command-line runner
tests/            unit tests + an offline end-to-end test
```

## Setup

Requires Python 3.11+.

```bash
git clone <this-repo-url>
cd <repo-folder>
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # Windows: copy .env.example .env
```

Then edit `.env`:

1. **Gemini API key** - create one at <https://aistudio.google.com/apikey> and set `GOOGLE_API_KEY`.
2. **Bucket** - set `STORAGE_BACKEND` (`gcs` or `s3`) and `BUCKET_NAME` to a bucket you own.
3. **Cloud login** (credentials stay on your machine, never in the repo):
   - GCS: `gcloud auth application-default login`
   - S3: `aws configure`

If `BUCKET_NAME` is left empty the pipeline still runs and builds the report locally; the
storage agent reports that uploads were skipped.

**Model and free-tier limits.** `.env.example` sets `PIPELINE_MODEL=gemini-3.6-flash`,
which responded reliably during testing (the default `gemini-3.8-flash` was timing out).
The Gemini free tier allows about 5 requests per minute per model and a run makes about 8,
so the agents automatically wait and retry on rate-limit (429) and overload (503/504)
errors. Expect a full run to take a few minutes.

## Run

```bash
python run_pipeline.py
python run_pipeline.py "Run the pipeline for the past month, magnitude 4.5 and up"
```

Open `output/report.html` in a browser. The same page is uploaded to
`<bucket>/earthquakes/reports/<run_id>/report.html`.

You can also use ADK's own tools from the repo root:

```bash
adk web            # chat UI at http://localhost:8000 - pick quake_pipeline, type "run the pipeline"
adk run quake_pipeline
```

### What lands in the bucket

```
earthquakes/raw/<run_id>/earthquakes.geojson
earthquakes/processed/<run_id>/events_clean.csv
earthquakes/processed/<run_id>/summary.json
earthquakes/reports/<run_id>/report.html
```

## Tests

```bash
pytest
```

The tests need no API keys or network. `test_pipeline_offline.py` runs the real agent
graph with a scripted stand-in for the model and a synthetic sample feed
(`tests/sample_feed.geojson`, generated by `tests/make_sample.py` - not real seismic data).

## Data source

USGS Earthquake Hazards Program real-time GeoJSON feeds:
<https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php>. No API key required.

## Security

No secrets are stored in this repository. `.env` and credential files are git-ignored;
`.env.example` contains placeholders only.
